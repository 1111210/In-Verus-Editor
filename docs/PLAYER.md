# 游玩器（3D）设计说明与进度

## 引擎选择

* 原编辑器用 tkinter，做不出 3D、也没有足够低的输入延迟，因此游玩器**独立**用
  **pygame-ce** 实现（已在 `requirements.txt` 里），**保留编辑器不动**。
* 没有引入 OpenGL / 新语言：pygame 的 `Surface` + 自写**透视投影**（`game/scene.py`）
  足够画几十个多边形，且能跑满 60~144 FPS；输入用 pygame 的事件队列
  （键盘 / 鼠标事件与帧解耦，避免 tkinter 的回调延迟）。
* 音频复用编辑器的 `rhythm_editor.audio.AudioPlayer`：倍速、系统延迟补偿、
  节拍音 / 打击音都已经在里面验证过（含“音效按软件位置触发”的规则）。

## 已实现（可直接用的部分）

| 模块 | 内容 |
| --- | --- |
| `game/judge.py` | 判定核心：EXACT / Exact / Near / Break（±25/50/100ms，提前 100~150ms 为 Break、更早是空敲不惩罚）；一次按键最多判定一个点击类物件；长按开头同点击类；长按 / 空域按**半拍一个判定区间**（离开 ≤50ms → EXACT、≤100ms → Exact、>100ms 但曾进入 → Near、从未进入 → Break；长按松键最多 Near）；滑键“吸附到最准确瞬间”（EXACT 立即、否则记录最好等级、过线 100ms 收尾）；空域 / 滑键判定范围两边各放宽 0.01；准度与分数公式 |
| `game/scene.py` | 3D 布局与透视：1 单位 = 鼠标合法区域宽 = 6K 中间四轨宽（1.5 单位总宽）；鼠标平面在 6K 上方 **0.4** 单位；两条判定线同处判定平面；相机在判定平面后方、鼠标平面上方 → 远处物件在屏幕上方且更小、鼠标平面看起来更宽；两个平面**运动距离相同**（同样的 `START_Z`） |
| `game/settings.py` | 玩家设置（全局文件 `player.json`，与编辑器设置分开）：玩家名、6K 键位（默认 shift/a/s/d/f/space）、物件厚度、音频延迟、1x 可视毫秒、侧轨高亮、鼠标灵敏度 0.1~10x、无界鼠标、音量 |
| `tests/test_game_judge.py`、`tests/test_game_scene.py`、`tests/test_game_settings.py` | 31 条测试覆盖上面的规则 |

## 需要你确认的模糊点（我按“最适合游玩”暂定）

1. **图形后端**：暂定 pygame 软件 3D（不装 OpenGL）。如果你想要更好的 3D/粒子效果，
   需要联网装 `PyOpenGL` 或换成别的引擎。
2. **6K 键位**：默认 `shift, a, s, d, f, space` 对应第 1~6 轨（`shift` 在最左）。
3. **一次按键最多判定一个物件**：满足条件时取**时间上最接近**的那个（并列时取 id 小的）。
4. **空敲**：比 -150ms 更早的敲击**不消耗**物件、也不计 Break（完全无惩罚）。
5. **长按**：头部命中后，区间内**只要松过一次键**该区间最多 Near；一直按住 = EXACT。
6. **空域/长按区间数**：按 `[start, end)` 每 0.5 拍一个，不足半拍的尾段不单独计。
7. **滑键**：同一时刻多个滑键时，鼠标位移区间与哪个相交就判哪个（可同时判多个方向相反的滑键）。
8. **准度分母**：用“已完成判定数”（进行中显示），分数分母用“总判定数”（含长按/空域的区间数）；
   总物件数按区间展开计算。
9. **分数**：`round(已取得准度 / 总判定数 × 1e8) + EXACT 数`（精确到整数）。
10. **无界鼠标模式关闭时**：判定用的横向位置与三角形标识都夹在 0..1；
    开启时用鼠标实际位置（可以超出）。
11. **首拍延迟 1.5s**：进入游玩后先空转 1.5s 再从第 0 拍开始（音频也从 offset 起播）。
12. **结算页**：按需求不显示准度，只显示分数与各判定数量。
