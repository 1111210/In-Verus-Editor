# 规格说明（逐条对照需求）

本文件把玩法与编辑器需求逐条展开，并标注实现位置与验证方式。

---

## 0. 玩法总览

游戏为**两个叠加平面**同时游玩：

1. **6K 下落式平面**：6 条轨道，物件自上而下（未来在上方）落向判定线。
   * 单轨按键：只占 1 条轨道。
   * 多轨按键：横跨相邻多条轨道（`lane_start..lane_end`）。
   * 长按：占据一段时间区间（可跨轨道）。
  * 显示：单键 / 多轨单键是**实心蓝色细矩形**（白边）+ 中间一条**白色横线**，
    矩形**以判定时刻为垂直中点**，所以白线正好压在节拍线上（厚度 `TAP_MIN_PX = 9px`）；
    长按是**实心蓝色矩形**（白边）+ 中间**白色竖线**（粗细与单键横线相同、
    不随跨轨道数变化），**开头处套用单键样式**（细矩形 + 压线的白色横线）；
    长按的**渲染宽度与单键一致**（编辑器与单键同一横向范围；游玩器按单键贴图的
    可见宽度向内收，见 `game/frame.py` 的 `TAP_VISIBLE_FRACTION`）。
2. **鼠标平面**：叠加在 6K 的**中间四条轨道**上（轨道索引 1..4，0 基）。
  * 空域：物件出现期间，鼠标必须停留在区域内；显示为**半透明蓝色**填充 +
     **不透明**边界线，且**只绘制左右两条边界线**（不画上下封口横线）。
   * 左右滑键：物件到达判定线时，鼠标要在滑键范围内朝指定方向滑动，
     滑动长度任意即判定成功；显示为**半透明绿色**填充 + **箭头**。

两个平面共用一条判定线与同一套时间网格，因此滚动 / 缩放天然同步。

## 1. UI

### 1.0 布局：编辑时分栏，演示时叠加

* **分界线可拖动**：两栏中间那条虚线就是分隔线，悬停时光标变成左右箭头，
  按住拖动**实时**改变两栏宽度（`Layout.split_ratio`，两边各留
  `config.SPLIT_MIN_PANE_PX = 150 px` 的最小宽度）；**双击分界线**恢复默认 1:3。
  拖动期间不会触发放置 / 选择工具，
  叠加（演示）模式下没有分界线。

* **编辑器**：画布左右分成两个独立区域 —— 左侧 6K 下落式、右侧鼠标平面。
  两个区域共用同一条判定线（同一个 y）与同一套时间网格，因此滚轮滚动、缩放
  天然同步；判定线在两侧都落在完全相同的拍上。
  宽度分配：**6K 只占约四分之一**（扣掉中间间隔后的 25%），其余全部给鼠标平面；
  鼠标平面在合法区域 0..1 之外还各留 `0.45` 的显示余量（显示范围 `-0.45 .. 1.45`），
  因此超出 0..1 的区域边界也看得见；再超出的部分**裁剪**在鼠标平面的显示边界处
  （不把显示边界画成物件边界，数据本身不变）；滑键箭头同样按真实位置裁剪，
  起点越界时照常画出可见部分，只有真实箭头端仍在显示范围内时才画箭头头 ——
  避免把箭头头挪到显示边界上、看起来像滑动终点落在那里。
* **演示模式**（`Tab`）：画布贴的是**游玩器的软件渲染画面**（3D 视角，只读，可暂停 / 继续）。
  没有 pygame 时退回编辑器自己的叠加视图：鼠标平面覆盖在 6K 的中间四条轨道上，
  演示区只占窗口宽度的 1/3 并居中（`config.OVERLAY_WIDTH_RATIO`），两侧留黑。
* 背景为纯黑（`#000000`）；窗口**默认最大化**启动（保留标题栏与任务栏），
  `F10` / 「视图 → 最大化 / 还原窗口」切换最大化，`F11` / 「视图 → 全屏切换」进入无边框全屏。
* 顶部工具栏只保留分组入口（文件 / 编辑 / 放置 / 视图 / 谱面设置）+ 播放 + 速度组 +
  编辑器设置 + **编辑物件** + **播放倍速（`−` 当前倍速 `＋`）**；
  具体功能全部收在**黑底二级菜单**里（缩放改在「视图 → 缩放」或 `Ctrl+滚轮`）。
  不保留系统菜单栏；演示模式只在「视图 → 演示模式」里，顶栏不设独立按钮，
  顶栏也不显示缩放程度文字。
* 「编辑物件」（仅选中 1 个物件时可用）**从二级菜单移到顶栏**，紧跟在「编辑」分组右侧。
* 窗口宽度不足时，工具栏自动出现**横向滚动条**（右侧的快速缩放与帮助固定不动，
  其余分组可左右滚动；也可以把鼠标放在工具栏上滚动滚轮）。
* **弹出窗口只有确认按钮**：设置 / 编辑 / 输入类对话框底部只保留「确定」（帮助、
  速度组面板保留「关闭」），取消改走 `Esc` 或关闭窗口，不再单列「取消」按钮；
  退出前的「未保存修改」询问只有「保存 / 不保存」（`Esc` = 放弃这次操作）。
* 菜单开合：点击分组按钮展开，**再次点击同一个按钮即收起**；点击别的分组按钮会直接
  切换；点击画布 / 其它控件、在画布上滚轮、或按 `Esc` 都会收起菜单。
* 缩放方向遵循直觉（菜单里：放大 = 屏幕内时间变少、物件变大），与 `Ctrl+滚轮` 一致。
* 滚动条样式：滑条体**白色**、背景（槽）**黑色**（竖向时间轴与工具栏横向滚动条一致）。

### 1.0.1 物件显示规则

* **判定线越过物件的判定时刻后，该物件不再显示**（默认；可用「视图 → 显示更早的物件」关掉这条限制）：
  * 单轨 / 多轨按键、鼠标滑键：越过它们的判定拍即消失；
  * 长按、空域：越过**结束时刻**才消失（按住期间整条长按 / 整个区域仍然可见）。
* 该规则只与“时间”有关，与位置无关：速度组把物件推回判定线附近时，只要它的判定时刻还没到，
  依旧会显示；已经判过的物件默认不画、也不能被点选（命中测试使用同一条规则）。
* 开启「显示更早的物件」后，已判过的物件仍然按真实位置画在判定线下方、可以点选；
  但**像素范围剔除照旧**：落不到可见区域里的物件（无论早多久）都不会绘制或参与命中，
  因此开销只与屏幕内的物件数量有关。

### 6K 区域

* 轨道边界：6 条轨道按等宽划分，交替底色 + 描边（`renderer._draw_lanes`）。
* 判定线：固定在游玩区高度的 80% 处（`config.JUDGMENT_LINE_RATIO`，可改）。
* 节拍网格：每拍细分为 `grid_division` 份（正整数，随时可改）；
  小节线按每个 BPM 段的“每小节拍数”重算并标出小节号与时间戳。
* 密度自适应：细分线间距过小时自动只画拍线 / 小节线，避免糊成一片。
* **拍号标注**：小节线旁标注「小节 N · 第 M 拍」，拍线旁标注「第 M 拍」，
  缩放得足够近时连细分格也标拍号（如「第 16.25 拍」）——方便照着画面填写各类
  以“拍”为单位的参数（BPM 起始拍、流速起始拍、物件时间等）。
  数据面板（BPM 与偏移、速度组、编辑物件）底部同时显示“当前判定线：第 X 拍（小节 Y 第 Z 拍）”。

### 鼠标区域

* 判定线：与 6K 完全同一拍（分栏时是右侧区域里的那条线，叠加时是同一条横线）。
* 节拍网格：与 6K 共用同一套网格参数。
* 合法游戏区域边界：分栏时是右侧区域里的矩形框；叠加时是中间四条轨道的矩形范围，
  用蓝色虚线框标出，标注 `(0 .. 1)`。
* 横向位置辅助网格：`horizontal_divisions = n` 表示把 0..1 合法区域 n 等分并画竖直虚线
  （`0` 表示关闭）。**没有单独的显示开关 —— 只要设置了等分就一定显示**；
  入口在「视图 → 横向辅助网格」（子菜单末尾有「自定义…」）。

### 滚动与吸附

* 滚轮：前后滚动时间（`Shift+滚轮` 加快），两个区域同步移动，因为它们共享同一个
  `ViewState.current_beat`。
* **滚轮一格 = 时间网格一格**（`1 / grid_division` 拍）；`Shift+滚轮` 一次 1 拍。
  滚动后一律调用 `snap_beat()` 吸附回网格，因此判定线不会停在格子之间。
* **判定线永远吸附到节拍网格**：任何滚动 / 跳转 / 步进都经过
  `ViewState.snap_beat`，吸附精度为 `1 / grid_division` 拍。
* 缩放：`Ctrl+滚轮`、`+/-` 或设置面板；缩放决定“屏幕上同时显示多长时间内的物件”。
  范围放宽到 **0.2 ~ 40 秒**（`ZOOM_MIN_SECONDS = 0.2`），可以放到很细对偏移。
* **右侧竖向滚动条方向是反的**：比例 `1.0` = 曲首、`0.0` = 曲末，
  往下拖 / 点下箭头 = 时间往回走（`scroll_fractions()` 与 `set_from_fraction()` 互为反向）。
* 视图菜单提供 **侧轨高亮**：开启后 6K 的第 1 / 第 6 轨背景变成暗紫色
  （全局设置 `side_lane_highlight`，默认关闭）。
* 视图菜单提供 **显示更早的物件**：开启后判定时刻已经过去的物件照常绘制在判定线下方
  （全局设置 `show_past_notes`，默认关闭）；仍然只画落在可见区域内的物件。

## 2. 工具栏

### 2.1 元数据设置

* 字段：歌曲名称、歌手、关卡难度名、难度等级（文本）、作者、音频文件名。
* 音频通过系统文件选择器（`tkinter.filedialog`）选择；选择后**复制到谱面文件所在的文件夹**，
  谱面中记录该文件名（相对路径）。
* 谱面尚未保存时会提示先保存（用户拒绝时复制到 `charts/unsaved/` 并给出提示）。

### 2.2 BPM 与偏移

* BPM 列表每项包含：从哪一拍开始变速、变速后的 BPM、变奏后每小节多少拍。
* 初始：从第 0 拍开始、120 BPM、每小节 4 拍。
* **从第 0 拍开始的一项不允许删除**（修改可以）；删除时弹窗拒绝。
* 同一拍重复添加会覆盖（自动去重 + 排序）。
* **BPM 变更处一定新开一小节**：变更拍**不必**落在上一段的小节线上，
  但它自己就是一条小节线；上一段末尾会留下一个**不完整的小节**，
  小节编号把它按一整节计入，因此变更后的第一拍正好是下一小节的第一拍。
  变更之后的网格按**新一段**的“每小节拍数”重新生长（每段起点重新起算）。
* **每小节拍数填 0 = 关闭小节线**：该段内不画任何小节线、也没有小节编号
  （只有拍线与时间标签），HUD 会显示“小节线已关闭”。之后重新填入正数即可恢复。
* **纵向比例按“秒”线性**：判定线以上固定显示 `zoom_seconds` 秒（每秒多少像素是常数），
  因此**BPM 变更处的时间轴格子会立刻改变大小** —— 高 BPM 段落每拍更短（格子更密），
  低 BPM 段落每拍更长；判定线跨过 BPM 变更时画面**不会整屏突变**。
  换句话说：相同的时间间隔永远对应相同的屏幕长度，而相同的拍数在不同 BPM 下长度不同
  （详见 `docs/DESIGN.md#坐标与运动`）。
* 偏移只设定一次：表示歌曲需要提前播放多少毫秒才能对上节拍，
  即第 0 拍对应歌曲位置 `offset_ms` 毫秒。

### 2.3 放置 6K 单轨按键

* 启用后点击 6K 区域 → 在鼠标所在轨道放置按键，时间自动吸附网格。
* 鼠标悬停时显示幽灵预览。

### 2.4 放置 6K 多轨按键

* 第一次点击记录：起点轨道 + 起点时间（吸附网格）。
* 第二次点击另一条轨道 → 生成跨越这两条轨道的多轨按键；
  **时间轴以第一次点击为准**（第二次点击的时间被忽略）。

### 2.5 放置长按

* 第一次点击：起点轨道 + 起点时间。
* 之后可以自由滚动与缩放，第二次点击决定结束时刻。
* 结束时刻**接收任意位置的点击**，包括鼠标游玩区域内部的点击；时间吸附网格。
* 切换工具或按 `Esc` 视为放弃本次操作。

长按工具**同时支持单轨与多轨**：
第一次点击记录起点轨道与起点时间（吸附网格）；第二次点击的**横坐标决定结束轨道**、
**纵坐标决定结束时间**（都吸附），于是同一个工具既能放单轨长按，也能一次拉出
“横跨相邻多条轨道的长按”；点在鼠标区域里则只改时间、轨道保持起点轨道。

* 若第二次点击的结束时间不晚于起点，会自动补一个网格格，保证是一条有效长按。
* 起点轨道与结束轨道会自动排序，保证 `lane_start ≤ lane_end`；
  之后可以用「编辑物件」继续调整轨道与起止拍。

### 2.6 放置空域

1. **先定时间**：第一次点击设定开始时间，第二次点击设定结束时间，都吸附网格。
2. **再定左边界**：依次点击左边界起点位置、左边界终点位置。
3. **然后定右边界**：依次点击右边界起点位置、右边界终点位置。
   * 位置以合法区域最左侧为 0、最右侧为 1，**允许超出**（如 -0.3 或 1.4）；
     开启横向辅助网格时位置吸附到网格线。
   * 放置过程中，**尚未点击的边界点按默认值渲染**：左边界视为位于 `0`、右边界视为位于 `1`，
     正在等待的那个点跟随鼠标预览，因此每一步都能看清形状。
4. **最后选线型**：弹出对话框选择左 / 右边界的**线型**（线性 / 缓入 / 缓出），
   也可以在这个面板里微调四个位置。

### 2.7 放置左右滑键

* 第一次点击：时间吸附网格；横向位置在开启横向辅助网格时吸附到**网格线上**
  （`k / n`），未开启时取点击处的横坐标。
* 第二次点击：决定滑动方向（向右 / 向左）与终点位置；两个位置相同则按最小跨度补齐。
  * 方向**始终按点击的左右关系判断**：即使两次点击被吸附到同一条网格线上，
    也会用未吸附的点击位置决定方向（第二次点在左边就是向左滑）。
* 判定规则（供未来游玩器实现）：物件到达判定线时，在滑键范围内朝箭头方向滑动任意长度即可。
* 显示：**向右**滑键为半透明**绿色** + 向右箭头，**向左**滑键为半透明**黄色** + 向左箭头
  （箭头始终从起点指向终点，与点击顺序一致）。
* **物件图层（自下而上）**：多轨长按 → 单轨长按 → 多轨单键 → 单轨单键 → 空域 →
  滑键 → 鼠标点击按键。
  这样即便谱面被有意写成非法重叠，小按键也压在长按之上、空域与滑键再压在最上面，
  交叠处依然可读；点击命中的优先顺序与图层一致。
  同一层里，多轨物件**跨的轨道越多越靠下层**（同跨度保持时间顺序）。
* 长度显示：**方框严格按实际长度绘制**（不做任何拉伸），只有箭头保留最小长度限制，
  保证很短的滑键也能看清方向。
* 放置预览：选择起点时只画**一根黄色虚线**标出即将放置的横向位置；选择终点时按方向给出
  **绿色（向右）/ 黄色（向左）** 的方框 + 箭头预览（方框同样按实际长度）。

### 2.7.2 放置鼠标点击按键

* 第一次点击：定**中心**位置（时间吸附网格）；第二次点击：点旁边定**大小**
  （横坐标差即半宽，不足最小时按最小半宽 `0.04` 补齐）。
* 横向摆放规则（**与滑键 / 空域一致**）：
  * **启用**横向辅助网格 → 吸附到网格线，并夹进 `0..1` 合法区域内；
  * **未启用** → 按鼠标真实位置放置，即使超出合法区域（出界）也照常放置。
  也就是说：只有开了横向辅助网格才会“吸附 + 夹取”，否则横向位置完全自由。
* 显示：**左右两条红色竖线**标出范围 + **中间一条红色横线**把两条竖线连起来
  （三条实线的粗细都与 6K 按键的中心实线相同，`theme.note_line_width`）
  \+ 中央一个**固定大小**的**红色实心菱形**（中心在正中间）。
  两条竖线的间距 = `2 × 半宽`、高度与 6K 单键相同，且**整体以判定时刻为垂直中点**
  （中间横线与菱形中心都落在时间网格线上）。
  菱形大小**不可编辑**，也不是谱面字段。
* 这是唯一的**最上层**物件：即使与滑键 / 空域重叠，红色实线与菱形也压在最上面。
* 玩法：物件到达判定线时，鼠标（**左键 / 右键均可**）点击在它的横向范围内即成功。
* 放置预览：选中心时画一根竖直虚线；选大小时按实际宽度给出**红色虚线**的两条竖线 + 中间横线
  \+ 红色菱形。
* 编辑 / 复制 / 镜像 / 撤销全部适配（`NoteEditDialog` 可改判定拍、中心、半宽）。

### 2.7.1 自动检查（放在「编辑」二级菜单）

「编辑 → 自动检查（谱面合法性）…」会对当前谱面做一次完整校验：弹出报告窗口，
并把有问题的物件**全部选中**（可以直接在画布上定位）。

**6K 下落式**（单轨 / 多轨 / 长按两两组合，共用一条规则）：

* 每条轨道在**任意时刻只能存在一个按键**：按键重叠、长按或多轨按键覆盖其它按键、
  长按之间相交、多轨按键之间相交、长按与多轨按键相交都会报出；
* **端点相接（紧贴）不算冲突**：长按在第 10 拍结束、另一个按键正好在第 10 拍 → 通过；
  但瞬时按键落在长按 / 多轨按键**内部**要报错。

**鼠标平面**（检查滑键与鼠标点击按键）：

* 滑键所在时刻若**没有任何空域** → 通过；
* 若该时刻存在空域，滑键的横向范围必须与该空域**相交或紧贴**（按该时刻空域边界曲线的
  实际位置判断），完全分离则报错。
* 鼠标点击按键与滑键规则相同，另外**同一时刻不能出现两个鼠标点击按键**。

### 2.8 编辑器设置（全局）

> **视图 / 音效 / 编辑器设置都是全局的**（存在 `%APPDATA%/InVerus/settings.json`，
> 其他系统 `~/.config/inverus/settings.json`，可用 `VERUS_SETTINGS` 覆盖），
> **不写进谱面文件**；老谱面的 `editor` 段会在首次打开时迁移一次。

1. **缩放**：屏幕上同时显示多长时间内出现的物件（秒），滑杆 + 精确输入。
2. **系统音频延迟**：从软件执行音频播放操作到电脑硬件放出声音的间隔（毫秒）。
   播放时用“后端位置 − 延迟 × 倍速”作为耳朵听到的位置来推进判定线
   （延迟是**真实时间**：慢放时真实 200ms 只相当于歌曲 100ms@0.5x，
   所以补偿必须按倍速缩放，否则音画差异会随倍速变化）。
   **允许负数**（`-5000 ~ 5000` ms）：负值表示声音比软件位置更早，此时会把差值加回来。
3. **演示视图设置**（「编辑器设置 → 演示视图设置…」）：编辑器演示模式专用的渲染参数
   —— 单键 / 多轨单键 / 滑键图案 / 鼠标点击图案的厚度、流速（可视毫秒 = 1500 / 流速）、
   侧轨高亮。与游玩器的 `player.json` **互相独立**；演示模式固定用软件渲染，
   帧率由编辑器主循环自适应（不跟随游玩器的「期望帧率」）。

> **网格设置在「视图」菜单的对应子级**：`时间网格细分 → 1/1 … 1/64`、
> `横向辅助网格 → 关闭 / 2…16 等分`，两个子菜单末尾都有 **「自定义…」**。
> 自定义**没有上限**（时间网格 ≥ 1；横向等分 ≥ 0，0 表示关闭）；
> 细分过密时网格线自动抽稀 / 退化成拍线，不会拖慢画布。

### 2.9 区域选择 / 复制 / 粘贴 / 镜像 / 编辑

* 选择：点击选中；空白处拖动 = 矩形框选。
* **Ctrl 选择**：把当前选择与上一次选择做**对称差**（两次都选中的物件会被取消选择）。
* 复制：`Ctrl+C` 记录选中物件数据。
* 粘贴：`Ctrl+V` 进入粘贴模式，点击目标时间即可粘贴；
  **轨道编号与横向位置保持不变**，整组物件按同样的时间偏移整体搬运。
* 镜像：沿游玩区域中轴线（即鼠标平面中线）翻转。
  * 6K 物件：轨道 `i → 5 - i`（并保持 `lane_start ≤ lane_end`）。
  * 空域：左右边界互换并整体镜像（`x → 1 - x`）。
  * 滑键：首尾位置镜像，方向随之反转。
* 编辑（仅单选时可用）：
  * 6K：编辑所处轨道（多轨编辑开始 / 结束轨道，始终保证开始轨道编号 < 结束轨道）、开始 / 结束拍。
  * 空域：分别编辑两条边界的线型与首尾位置。
  * 滑键：编辑首尾位置（以及判定拍）。

### 2.10 速度组

* 初始有一组“默认组”，**不可删除**，可编辑。
* 每组的速度是一个列表（与 BPM 列表结构相似）：从哪一拍（浮点数）开始，
  流速变为默认速度的几倍（可为正数、0、负数）。
* 每个物件记录自己属于第几组；每个组也记录包含哪些物件 id（双向一致，
  读档时会自动修复不一致的数据）。
* 删除速度组时，组内物件全部回到默认组。
* **位置推算**：物件在判定时刻必然位于判定线上；其它时刻的位置由所属速度组的流速反推：

  ```
  D(t) = ∫_{t}^{t_judge} v(u) du          v = 该组在拍 u 的流速倍率
  屏幕 y = 判定线 y − D(t) × 每拍像素
  ```

  `t` 为判定线当前所在的拍（判定线永远吸附网格，因此 `t` 恒为网格值）。
  `D > 0` 表示物件位于判定线上方（未来侧）；流速为负时物件会被推向判定线下方，
  实现“暂停 / 反向”等特效。
* 流速可以正负混用并叠加，**位置不是判定时刻的单调函数**：远处的物件可能被推回判定线上，
  近处的物件也可能被甩出画面。因此渲染剔除只看实际像素位置，绝不用“拍差”判断可见性
  （详见 `docs/DESIGN.md` 的“非单调速度”一节）。
* **演示视图与游玩器的物件位置同样按速度组反推**（`game/frame.py::scroll_ms`）：
  判定时刻落在判定平面上，其它时刻由所属速度组的 ``∫ v·spb dτ`` 换算；
  剔除与同层绘制顺序也按这个滚动距离，而不是拍差。
* **判定线之前的可见段**：相机在判定平面后方，反向流速的物件会走到判定线更靠近
  摄像头的一侧（``z < 0``）。可见下界由 `PlayerScene.visible_z_near` 按窗口尺寸
  估算（投影二分到画面下缘），物件落在「可视下界 ~ 运动起点」之间就照常绘制。
* **判定区间里已经过去的部分不画**：长按 / 空域即使还在判定中，也只画从当前时刻
  到结束时刻的那一截（不会在判定线之前拖出已经判过的尾巴）。

### 2.11 播放 / 暂停

* 空格或工具栏按钮；可从任意位置（判定线所在拍）开始播放。
* 播放时按“听到的位置”推进：`chart_time = (后端位置 − 系统延迟) − 偏移`。
* **暂停时判定线自动吸附到时间轴刻度**（网格），并同时把音频位置对齐到该拍。
* **起播位置就是裁剪位置**：音效时刻表按判定线所在拍裁剪过去的条目，
  往回滚再播放时中间那一段照常发声（不会因为沿用旧暂停位置而整段静音）。
* **音乐与谱面都播完 3 秒**（`config.PLAY_END_MARGIN_SECONDS`）才自动暂停；
  没有载入歌曲时不会自动停止（静音时钟一直走）。

### 2.11.0 音效菜单：节拍音 / 打击音效 / 音量

顶栏有一级菜单「**音效**」：

* **打击音效（开关）**：全局设置 `hit_enabled`，默认开启；
* **节拍音**：关闭（默认）/ 小节音 / 节拍音 —— 相当于“是否启用”； 
* **音量…**：打开音量窗口（音乐 / 节拍音 / 打击音三路滑杆）。

顶栏顺序：**文件 / 编辑（合并）→ 谱面设置 → 放置物件 → 编辑物件 →
视图 → 速度组 → 音效 → 编辑器设置**，最右端固定 **▶ 播放 / 暂停**与播放倍速；
**「编辑器设置」菜单里还有演示视图设置与帮助（操作指南 / 快捷键）**。

* 「视图 → 节拍音」三选一：**关闭（默认）** / **小节音** / **节拍音**
  （存进谱面的 `editor.metronome` 字段，读档沿用；缺字段按关闭处理）。
* 开启后播放时发声：**小节音**在每个小节线响一声（BPM 变更处一定有声），
  **节拍音**在每一整拍响一声；小节音音高更高（1320Hz vs 880Hz），便于区分。
* **预先算好、混进音频输出**：`metronome.effect_events()` 一次算出整条时间轴上
  所有音效的**歌曲毫秒时刻**，音频层在合成播放窗口时把到点的音效直接叠加进输出流
  （不再是逐帧判断 / 逐声触发）。因此极高 BPM（一帧跨多个判定区间）不会漏响，
  掉帧 / 卡顿同样不漏；跳转 / 暂停恢复只混起播位置之后的音效，不补发一串“滴”声。
* **慢放不改变这一声的长度**：音效不参与歌曲的时间伸缩，固定 45ms（`CLICK_MS`）、
  音量 0.20；倍速只决定音效落在输出的哪个位置
  （`输出位置 = (时刻 − 窗口起点) / 倍速`），两声之间的**间隔**跟着音乐走。
* **时刻表增量维护**：节拍音只由 BPM / 每小节拍数 / 偏移 / 模式决定；
  打击音跟着谱面内容走（`Document.revision`）。改物件只重算打击音那一半，
  改音量 / 倍速完全不重算，覆盖范围按 30 秒取整缓存；无变化的 tick 只比较缓存键。
* 播放中改时刻表：变化落在**当前窗口还没播到**的部分时（例如播放中在判定线
  前方放物件、开关打击音），从当前位置重合成当前窗口，音效**立刻生效**
  （音乐从当前位置继续）；只影响到后面的窗口时重合成“排队窗口”即可。
* 播放中改音量：歌曲音量与音效音量都烘在缓冲里，所以同样从当前位置重合成
  当前窗口，**立刻生效**；“音乐 / 节拍音 / 打击音”一起改也只重合成一次。
* 没有 pygame / 音频设备不可用时静默降级，开启时状态栏会提示“暂时听不到声音”。

### 2.11.0.1 打击音效（默认开启）

* 每个物件在**开头的判定时刻**响一声白噪声（45ms，与节拍音同长度、同包络、同基准音量）：
  * 单键 / 多轨按键 / 左右滑键 / 鼠标点击按键 → 判定时刻；
  * 长按、空域 → **开头的时刻**（`head_beat`），中段不重复响。
* 同一时刻的和弦只响一声（`effect_events()` 按时刻去重）。
* 与节拍音一样**混进歌曲输出、不参与歌曲重采样**，
  慢放不会改变这一声的长度与音色。
* **天然与音乐对齐**：音效与歌曲在同一路输出里、经过同一段系统延迟，
  不需要额外的触发补偿；`audio_latency_ms` 只作用于判定线
  （判定线用“耳朵听到的位置”，见 2.11）。

### 2.11.0.2 音量（编辑器设置）

「音效 → 音量…」窗口里三个滑杆（0 ~ 100%），写进谱面 `editor` 段、读档沿用：

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `music_volume` | 1.0 | 歌曲音量 |
| `metronome_volume` | 0.6 | 节拍音音量 |
| `hit_volume` | 0.6 | 打击音效音量 |

播放中拖动音量滑杆（确认后）会立刻听到变化：音频层从当前位置重合成正在播的
窗口，音乐接着往下走；暂停时改音量则从下一次播放开始生效。

### 2.11.1 播放倍速（变速变调：慢放音调变低）

* 顶栏右侧的 `［−］［当前倍速］［＋］` 控制播放倍速：**0.1x 一档，范围 0.01 ~ 1.0x**；
  从 0.1x 继续减速进入 **0.01 一档的细档**（0.09 → 0.08 → … → 0.01），文字相应显示两位小数。
* 变速同时作用于**谱面推进速度**与**音频速度**：
  * 谱面推进速度：判定线按倍速前进（`current_beat` 由音频位置换算，天然同步）；
  * **不改变绘制的物件间隔**：缩放 / 网格 / 物件位置都按原样绘制，只是时间推进变慢；
  * 音频：把样本**线性插值重采样**拉长后再按原速播放 —— 等价于“把采样率降低 rate 倍”，
    所以慢放 0.5x 时长度翻倍、**音调降低一个八度**。
* 需要 `numpy` 做向量化重采样（`requirements.txt` 已列出）。没有 numpy 时倍速固定 1.0x。
* 播放中改变倍速会先停掉旧后端再从当前位置重新开始，不会出现两个后端同时出声。
* **播放中改倍速会自动暂停**（停在当前位置，按空格用新倍速继续）：
  无缝切换后端容易出现片段错乱，因此使用显式暂停，状态栏会给出提示。
* 合成窗口按输出时长固定（`STRETCH_TARGET_OUTPUT_MS = 8s`）：
  **pygame 通道只认一个排队块**（实测排 3 个只播 1 个），所以调度是
  “当前窗口 + 一个排队窗口”，按时间锚点补块，并在通道空掉时立刻补播；
  单次重采样约 15~35ms、8 秒一次，界面不会因为合成而卡顿。

### 2.12 演示模式

* `Tab` 或工具栏按钮进入 / 退出。
* 画布显示的是**游玩器软件渲染的 3D 画面**（`game/softview.py` 复用 `PlayerApp`
  的绘制方法），与游玩器的软件渲染逐像素一致；只是**不画**分数、判定、
  元数据、菜单等 HUD，因此也没有判定与计分逻辑。
* **不支持编辑**（点击不会产生物件、不能选择）；隐藏工具栏、状态栏与时间轴滚动条。
* 支持**随时暂停 / 继续**（空格）：暂停停在当前时刻，**不吸附网格**（与游玩器一致），
  继续播放从同一位置接续；画面左上角有一行编辑器提示（空格 / Tab / Esc）。
* **不渲染鼠标指针**（只读预览，不需要指针）；画面参数来自「编辑器设置 →
  演示视图设置…」——物件厚度 / 流速 / 侧轨高亮，与 `player.json` 独立，
  渲染后端固定软件渲染。
* 没有 pygame 时退回编辑器的叠加视图（`LAYOUT_OVERLAY`），此时仍可滚动 / 缩放 / 播放。
