# 设计文档

## 1. 总体结构

```
             ┌──────────────────────────── EditorApp (app.py) ────────────────────────────┐
             │  Tk 主窗口 · 工具栏 Toolbar · 画布 Canvas · 状态栏 · 播放循环 · 全部命令      │
             └───────┬───────────────────────┬───────────────────────┬────────────────────┘
                     │                       │                       │
             Document (model/document.py)   ViewState (ui/view.py)  AudioPlayer (audio.py)
             谱面 + 选择 + 剪贴板 + 撤销     屏幕↔拍换算 / 吸附 /      pygame.mixer 或
                                            缩放 / 几何布局           静音时钟 + 延迟补偿
                     │                       │
              Chart (model/chart.py)         │
              元数据 / 时间轴 / 设置 /        │
              速度组 / 物件                  │
                     │                       │
       TimingMap(拍↔秒) SpeedGroup(流速积分)  │
                     └───────────┬───────────┘
                                 │
                  Renderer (ui/renderer.py) → Scene (ui/scene.py) → Tk Canvas 图元
                  ToolController (ui/interactions.py) → Document 编辑命令
```

分层原则：

* `model/` 与界面完全解耦（可无界面运行、可单元测试）。
* `ui/` 只做“展示 + 交互 → 命令”，不保存谱面状态。
* 所有修改都经由 `Document`，因此撤销 / 脏标记 / 窗口标题完全一致。

## 2. 坐标与运动

### 2.1 三个坐标系

| 坐标系 | 单位 | 用途 |
| --- | --- | --- |
| 拍（beat） | 1 拍 = 时间网格的基本单位 | 一切物件的时间都用拍记录 |
| 网格距离（grid distance） | 默认流速下 1 拍 = 1 个距离单位 | 物件在判定线上方的“高度” |
| 屏幕像素（px） | `每拍像素 = 判定线以上像素 / 可视拍数` | 最终绘制 |

### 2.2 判定线永远吸附网格

`ViewState.current_beat` 是“判定线当前所在的拍”。
所有滚动 / 跳转 / 步进 / 缩放后都调用 `snap_beat(beat) = round(beat × division) / division`，
因此判定线总是落在时间网格线上，物件位置与网格严格一致。

### 2.3 网格（时间轴）映射

```
y(beat) = judgment_y − (beat − current_beat) × 每拍像素
每拍像素 = (judgment_y − play_top) / 可视拍数
可视拍数 = zoom_seconds / 当前 BPM 的秒每拍
```

* `zoom_seconds`（缩放）表示“屏幕上同时显示多长时间内的物件”；
* 换成拍数时使用**判定线所在处**的 BPM，因此变速点前后网格间距保持一致（同一张网格），
  而“屏幕内显示多少秒”的意义不变。
* 由此可得：**同样的拍差 = 同样的长度**，与 BPM 列表无关，
  即 BPM 不会影响物件运动速度。

### 2.4 物件映射（速度组）

```
D(t)    = ∫_{t}^{t_judge} v(u) du        （速度组积分，v 为流速倍率）
y_note  = judgment_y − D(t) × 每拍像素
```

* 判定时刻 `t = t_judge` 时 `D = 0`，物件一定在判定线上；
* `v ≡ 1` 时 `D = t_judge − t`，与网格映射完全一致（默认速度与时间轴网格对齐）；
* `v < 0` 时 `D` 变号 → 物件被“推”到判定线下方，形成反向特效；
* 积分是分段常数函数的积分，`SpeedGroup.cumulative` 逐段累加，复杂度 O(段数)，
  段数极少，因此可以直接在每帧渲染中调用。

### 2.5 非单调速度：不能用“拍差”做任何判断

流速列表允许正数、0 与负数，且各段叠加。于是 **物件的屏幕位置不是判定时刻的单调函数**：

* 远处（判定时刻相差很多拍）的物件可能被推回判定线上；
* 近处的物件可能被甩出画面，甚至跑到判定线下方很远处；
* 两个不同的判定时刻可能落在同一个屏幕位置。

例如 `v = 1 (0..10) → -1 (10..20) → 1 (20..)`：

```
判定线在 10 拍时，判定时刻 30 拍的物件：D = ∫₁₀³⁰ v = -10 + 10 = 0 → 正好落在判定线上
判定线在 10 拍时，判定时刻 20 拍的物件：D = -10              → 被推到判定线下方
```

因此实现遵守两条硬性约束：

1. **可见性剔除只按算出来的像素位置**（`ui/renderer.py::_draw_notes` 先算 y 再决定是否绘制），
   绝不用“拍差大于阈值就跳过”这类粗暴判断；
2. **命中测试与渲染共用同一套几何**（`ui/geometry.py`），保证“看到的”就是“点得到的”。

停留区域的上下边界随流速变化，必须在速度段边界处取折点，否则折点会被直线糊掉：
`geometry.sample_beats()` 会强制把落在区间内的速度段起点加入采样点，渲染与命中测试都使用它。

长按 / 多轨按键的“条身”按标准 SV 表现绘制为**两端点位置之间的直杆**：
两端各自位于它们的映射位置，流速造成的压缩、拉伸乃至上下翻转都会如实体现。

## 3. 渲染管线

### 3.0 两种布局

* `LAYOUT_SPLIT`（编辑器默认）：画布左右两个区域，`Layout.pane_6k` 与 `Layout.pane_mouse`
  分别给出边界；`lane_rects` 只落在 6K 区域内，`mouse_left/mouse_right` 是鼠标区域里
  0..1 合法区域的左右界。两个区域共用 `judgment_y` 与 `beat_to_y()`，所以时间轴严格同步。
  6K 区域取 ``SPLIT_6K_RATIO = 0.25``；鼠标区域把 ``MOUSE_OVERFLOW_NORM = 0.45`` 的归一化
  余量分给两侧，于是显示范围是 ``-0.45 .. 1.45``，而 ``norm_to_x()`` 会把更远的值截断在
  区域边界上（只影响显示，不改数据）。
* `LAYOUT_OVERLAY`（演示模式）：`pane_mouse` 直接取中间四条轨道，鼠标平面叠加在 6K 上。

`ViewState.set_layout_mode()` 切换时会 `recompute()`；`lane_at()` 在 6K 区域之外返回 `None`，
因此放置类工具天然不会把 6K 物件放到鼠标区域里。

`Scene`（`ui/scene.py`）是一个**带差分的画布封装**：

* 每帧 `begin()` → 用稳定 key 声明图元（`rect/line/polyline/polygon/oval/text`）
  → `end()` 自动删除本帧未出现的图元；
* 图元坐标与选项与上一帧完全相同时**不触碰** Tk 对象，只有变化时才 `coords/itemconfigure`；
* 因此 60 FPS 下开销与“变化量”成正比，而不是与物件总数成正比。

场景还维护**显式图层**（`set_layer`）：Tk 画布的对象层级由创建顺序决定，
切换布局时某些对象会被删除再重建，如果不排序，新建的区域底色会跑到最上层把物件盖住。
`Scene.end()` 在检测到重建后按图层号 `tag_raise`，保证
「背景 < 区域底色/轨道 < 网格 < 合法区域与横向网格 < 物件 < 判定线 < 预览 < 总览条 < HUD」
始终成立（对应回归测试 `test_layer_order_survives_layout_switch`）。

绘制顺序：背景 → 轨道 → 合法区域边界 → 时间网格 → 横向辅助网格 → 物件
→ 判定线 → 幽灵预览 / 橡皮筋 → HUD 文字（时间轴导航交给右侧的 ttk 竖向滚动条）。

物件内部固定为**六层，自下而上**（`Renderer._draw_notes`）：

```
多轨长按 → 单轨长按 → 多轨单键 → 单轨单键 → 空域 → 滑键
```

顺序刻意“从大到小”：即使谱面被有意写成非法重叠（长按里套按键、空域压住按键等），
小按键也压在长按之上、半透明空域与滑键再压在最上面，交叠处依然可读。
命中优先级（`geometry._depth`）与这套图层**完全一致**，保证“点到的就是你看到的”。

物件的可见性有两道判据，二者互不替代：

1. **像素范围**（`_draw_notes` 内按算出的 y / 多边形包围盒剔除）——
   因为流速可正可负，不能用拍差判断远近；
2. **判定时间**（`geometry.note_in_time`）—— 判定线越过物件的判定时刻后不再显示，
   长按与停留区域按 `tail_beat` 计算。渲染与命中测试共用这条规则。

### 3.1 命中测试复用渲染几何

渲染器每帧把“真正画出来”的物件（已过可见性与显示规则过滤）连同它们的包围盒
（空域还带多边形）写进 `geometry.HitCache`：

* 点击 / 框选（`notes_at` / `notes_in_box`）优先查询这份缓存，只遍历屏幕内的物件，
  不再对整张谱面重算几何；缓存命中时每帧成本与“可见物件数”成正比；
* 缓存带**视图签名**（判定线位置、每拍像素、画布尺寸、物件数量），
  视图或谱面一变就失效，此时自动回退到全量扫描，保证结果总是正确的；
* 10000 物件实测：一次命中 74.7 ms（全量）→ **0.010 ms**（缓存）。

网格文字（`_draw_time_grid`）承担“照着填数据”的职责：小节线写「小节 N · 第 M 拍」，
拍线写「第 M 拍」，细分格在间距足够时写小数拍号；密度不足时逐级隐藏，
避免糊成一片。

Tk 画布没有 alpha 通道，半透明用 `stipple`（点阵）模拟：
停留区域填充 `gray50` + 不透明描边，滑键填充 `gray50` + 不透明箭头，
与规格要求的“半透明填充 + 不透明边界”一致。

停留区域只画**左右两条边界曲线**（含放置时的幽灵预览），不画上下封口横线：
区域的语义由两条边界曲线定义，封口横线只会在时间起止处形成多余的横线。

空域的边界形状（左右两条曲线）**只在可能显示时才计算**：

1. 先按显示规则（判定时间未过）过滤；
2. 再做便宜的可见性预判 —— 匀速速度组用可视**时间窗** O(1) 排除；
   非匀速组在“速度段边界 + 等分点”上采样判断（每段内位置线性，采样是精确的），
   这一步只算 y；
3. 只有可能可见的空域才去算左右边界曲线（缓动求值 + 坐标变换），
   采样点数还会按屏幕高度自适应（越高越密，最矮时 4 点）。

## 4. 交互状态机

`ToolController`（`ui/interactions.py`）持有唯一的“未完成操作”状态：

| 工具 | 第一次点击 | 第二次点击 | 备注 |
| --- | --- | --- | --- |
| 选择 | 选中 / 开始框选 | 释放时确定框选结果 | Ctrl = 与上次选择做对称差 |
| 单轨按键 | 直接放置 | — | 悬停时显示幽灵 |
| 多轨按键 | 记录起点轨道与时间 | 另一条轨道 → 生成 | 时间以第一次点击为准 |
| 长按 | 记录起点轨道与时间 | 任意位置（含鼠标区域）→ 结束时间 | 期间可滚动 / 缩放 |
| 停留区域 | 记录开始时间 | 记录结束时间 → 弹出边界设置 | 边界位置允许超出 0..1 |
| 左右滑键 | 记录时间与起始横坐标 | 决定方向与终点 | 开启横向网格时吸附网格线 |

`Esc` 或切换工具会调用 `cancel_pending()` 放弃未完成操作。
粘贴模式（`Ctrl+V` 后）是独立状态，任意点击确定目标时间。

## 5. 撤销 / 重做

采用**整谱快照**：`Document.push_undo(label)` 深拷贝 `chart.to_dict()` 并记录当前选择。
理由：谱面数据量小（数千物件 < 1 MB），快照实现简单、不会漏字段，
且能连同选择状态一起回滚。栈上限 200 步。

所有命令（放置、删除、粘贴、镜像、编辑、元数据、BPM、设置、速度组）都通过
`Document.apply()` 走同一条路径，所以“撤销”按钮的标签始终准确。

### 5.1 物件排序缓存

渲染、导出与命中测试都需要“按判定时刻排序”的物件列表（`sort_key = (head_beat, tail_beat, id)`）。
`Chart.sorted_notes()` 会把结果缓存在 `_sorted_cache` 里，只在必要时重建：

* `Chart.add()` / `Chart.remove()` 自动失效；
* `Document.apply()`（放置、删除、粘贴、镜像、编辑物件、改 BPM……）统一失效，
  因此**就地修改**物件时间（例如镜像后再改拍）也不会留下脏缓存；
* 外部直接改物件数据时应显式调用 `Chart.invalidate_order()`；
* 10000 物件实测：每帧排序 1.16 ms → **0.000 ms**（只在编辑后的第一帧重建一次）。

## 6. 音频与延迟补偿

* 后端抽象：`PygameBackend`（pygame.mixer.music，支持 mp3/ogg/wav 与 seek）与
  `SilentBackend`（`time.perf_counter()` 时钟，无声音但功能完整）。
* 未安装 pygame 时自动退化，状态栏明确提示，不会影响编辑。
* 延迟补偿：`audio_latency_ms` 表示“软件执行播放 → 硬件出声”的间隔，
  播放时使用 `后端位置 − 延迟` 作为“耳朵听到的位置”来推进判定线，
  这样屏幕与听到的声音是对齐的。
* 暂停时：先把当前听到的位置换算成拍并吸附网格，再让音频停在“该拍对应的歌曲位置”，
  保证“继续播放”从判定线所在处接续。

## 7. 数据一致性

* 物件的 `group` 字段与速度组的 `note_ids` 双向记录；
  `Chart._repair_groups()` 在读档后修复不一致（比如手工编辑过的 JSON），
  保证“每个物件一定有归属，且只有一个归属”。
* 默认组（id = 0）永远存在，不可删除；删除其它组时其物件回到默认组。
* 第 0 拍的 BPM 记录与流速记录强制存在（只允许修改），避免除零与未定义区间。

## 8. 性能

* 渲染：差分场景 + 可见区间剔除（视口外的物件不生成图元）。
* 网格：细分线过密时自动降级（只画拍线 / 小节线）。
* 速度积分：分段常数求和，O(段数)。
* 主循环：`after(16, ...)` ≈ 60 FPS；空闲时同样保持轻量（差分命中率极高）。

## 9. 可扩展点（为后续播放器预留）

* 游玩器只需读取同一份 JSON：判定数据就是“判定拍 + 轨道区间 / 区域边界 / 滑动方向”。
* `SpeedGroup` 的位置推算函数可直接复用在播放器里以驱动特效画面。
* 音频时间轴（拍 ↔ 歌曲毫秒）已经在 `TimingMap` 中集中实现，播放器可直接复用。
