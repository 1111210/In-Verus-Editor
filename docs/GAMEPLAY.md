# 玩法与判定规则

本文档是玩法的**唯一语义说明**：编辑器按它渲染与校验，游玩器按它判定与计分。

* 编辑器只负责**创作**：它允许写出非法谱面（例如故意重叠按键），供玩家体验
  “明知违规但可读”的展示；合法性由「编辑 → 自动检查（谱面合法性）」给出。
* 游玩器**不拒绝**任何谱面，遇到非法重叠时按第 8 节的策略逐条降级。
* 实现位置：判定在 `game/judge.py`，画面在 `game/frame.py` + `game/app.py`，
  共用的数据模型在 `model/`。

---

## 1. 两个平面

一张谱面同时包含两个平面，它们**共用同一条判定线、同一套时间网格**：

| 平面 | 内容 | 编辑时 | 演示 / 游玩时 |
| --- | --- | --- | --- |
| 6K 下落式 | 单轨按键、多轨按键、长按 | 左栏（约占 1/4 宽） | 叠加在中间四条轨道上 |
| 鼠标平面 | 空域、左右滑键、鼠标点击按键 | 右栏 | 横跨中间四条轨道（`lane 1..4`） |

* 编辑器默认**左右分栏**，只有演示模式才**叠加**显示；游玩器一律按**叠加**呈现。
* 横向坐标统一为**归一化** `x`：合法区域最左侧 = `0`、最右侧 = `1`，
  允许超出（例如 `-0.3`、`1.4`）；超出部分在编辑器里也能看见（显示范围 `-0.45 .. 1.45`）。
* 竖直方向：物件“到达判定线”的位置就是判定线上，`y = judgment_y`。

## 2. 时间：拍、秒与判定时刻

* 谱面以**拍（beat）**为时间单位；`timing.bpm_segments` 给出每段 BPM 与每小节拍数，
  `timing.offset_ms` 表示第 0 拍对应歌曲位置 `offset_ms` 毫秒。
* **每逢 BPM 变更一定新开一小节**：变更拍不必落在上一段的小节线上，但它自己就是一条
  小节线；上一段末尾不完整的小节按一整节计入编号。变更之后的网格按新一段的
  `beats_per_bar` 重新生长（每段起点重新起算），游玩器可以直接依赖这条不变量。
* `beats_per_bar = 0` 表示这一段**关闭小节线**：该段内没有小节线与小节编号，
  只有拍线；`bar_lines()` 会跳过它，`bar_index_at()` 返回之前累计的小节数。
* 拍 ↔ 秒的换算**只**取决于 BPM 段：
  `seconds(beat) = offset_ms/1000 + ∫ 60/bpm(beat) dbeat`。
* **纵向映射按秒线性**（`每秒像素 = 判定线以上像素 / zoom_seconds` 是常数），
  所以 BPM 变更处之后的格子会**立刻**变密 / 变疏，判定线跨过变更点时不会整屏突变；
  游玩器沿用这套映射，因此游玩画面与编辑器的时间轴完全一致。
* 每个物件记录的是**判定时刻**：该时刻物件应当正好压在判定线上。
* **判定窗口**（以真实时间为准，不随倍速改变）：`±25 ms` 为 EXACT、`±50 ms` 为 Exact、
  `±100 ms` 为 Near；提前 `100 ~ 150 ms` 记 Break，更早的敲击不计入判定也不惩罚。
  长按头 / 尾使用同样的窗口。窗口定义在 `game/judge.py`，不写进谱面。

## 3. 速度组：物件位置由 ∫v 反推（**不是**单调的）

* 每个物件属于一个**速度组**（`group`，`0` = 默认组）。速度组是一条
  `(起始拍, 倍率)` 列表，倍率 = 流速 / 默认流速，**可以为 `0`（停留）或负数（反向）**。
* 物件的屏幕位置由“判定时刻必须落在判定线上”反推（`spb` = 该拍所在 BPM 段的秒每拍）：

  ```
  D(t) = ∫[t, beat] v(τ) · spb(τ) dτ      （“滚动秒数”）
  y(t) = judgment_y − D(t) × 每秒像素
  ```

  其中 `t` 是当前播放位置、`beat` 是物件的判定时刻。
* 由于流速可正可负且会**叠加**，`D(t)` **不是** `t` 的单调函数：
  远处的物件可能被推回判定线上，近处的物件也可能被甩出画面。
  **任何“按时间线性排序”的实现都是错的** —— 包括剔除、命中测试、绘制顺序。
* 编辑器与游玩器共用的做法：
  * 剔除只按算出的位置判断：编辑器用 `∫v` 反推出的**拍区间**（`ViewState.beat_range()`），
    游玩器用按所属速度组积分出的滚动距离（`game/frame.py::visible_notes()`：
    距离在下界之外的物件先用“最小流速 × 歌曲时间差”快速排除，再精确积分）；
  * 反向流速的物件会走到判定线**更靠近摄像头的一侧**：游玩器把“判定线之前”
    的可见范围估算为相机对该平面的可视下界（`PlayerScene.visible_z_near`，
    按窗口尺寸把投影二分到画面下缘），落在「可视下界 ~ 运动起点」之间就照常绘制；
  * **判定区间里已经过去的部分不画**：长按 / 空域即使还没判完，也只画
    「当前时刻 → 结束时刻」这一截，不在判定线之前拖出已判过的尾巴；
  * 命中测试复用渲染时算出的几何（`ui/geometry.py` 的 `HitCache`）。

## 4. 物件一览

渲染与判定都遵循**同一套图层顺序**（自下而上，越靠上的越优先被点到）：

```
多轨长按 → 单轨长按 → 多轨单键 → 单轨单键 → 空域 → 左右滑键 → 鼠标点击按键
```

同为多轨长按 / 多轨单键时，**跨越轨道越多越靠下层**（保证小物件不被盖住）。

### 4.1 单轨按键（`type: "lane"`，`lane_start == lane_end`，`beat_end == beat_start`）

* 显示：白边 + 亮蓝环的矩形，中间一条白色横线。
* 判定：判定时刻，所属轨道对应的按键（键位映射由游玩器设置决定）被按下。
* 同一轨道**同一时刻只能有一个按键**（长按内部也算“占用”）。

### 4.2 多轨按键（`type: "lane"`，`lane_start < lane_end`）

* 显示：与单轨按键同样的矩形，横向跨越 `lane_start..lane_end`。
* 判定：判定时刻，**该范围内所有轨道**都必须同时被按下（游玩器把这些轨道视为一个整体，
  语义是“覆盖面内的轨道全部命中”）。
* 多轨按键不允许与其它按键在同一轨道的同一时刻重叠。

### 4.3 长按（`type: "lane"`，`beat_end > beat_start`，可跨轨道）

* 显示：两侧亮蓝竖线 + 中间一条白色竖线（粗细与单键一致，**不随跨轨道数变化**），
  开头处一条与单键相同的白色横线；内部不填充。
* 判定：
  * 头部：判定时刻按下（窗口同普通按键）；
  * 持续：在 `(beat_start, beat_end)` 区间内保持按住；
  * 尾部：在 `beat_end` 附近（窗口同普通按键）松开即算完整。
  * 中途松开视为断连（记 Break 并中断连击）。
* 长按在区间内**占用**它覆盖的所有轨道：其它按键不得与它相交（端点相接不算）。

### 4.4 空域（`type: "region"`）

* 语义：在 `[beat_start, beat_end]` 期间，**鼠标必须待在空域内**。
* 形状：左右两条边界线，各自的 `start` / `end` 与缓动 `linear | ease_in | ease_out`
  由谱面给出；任意时刻 `t` 的左右边界为

  ```
  left(t)  = lerp_ease(left.start,  left.end,  progress(t))
  right(t) = lerp_ease(right.start, right.end, progress(t))
  progress(t) = (t − beat_start) / (beat_end − beat_start)
  ```

  `progress` 之外的时刻（物件还没出现 / 已经过去）不参与判定。
* 判定：按**半拍一个判定区间**评级 —— 鼠标位置由“鼠标事件时间戳 + 每帧采样”组成的状态
  时间线给出，区间内不在区域里的时长按时间戳累计（一帧跨多个区间也算得准）：
  整段都在区域内 → EXACT；离开 ≤ 50 ms → EXACT；≤ 100 ms → Exact；
  更久但曾进入 → Near；从未进入 → Break。
* 边界允许超出 `0..1`（编辑器只画左右两条边线，不填充上下端）。

### 4.5 左右滑键（`type: "slide"`）

* 语义：判定时刻鼠标在滑键范围内，并**朝指定方向滑动**。
* 方向：`x_end > x_start` → 向右；`x_end < x_start` → 向左（编辑器：向右半透明绿、
  向左半透明黄；箭头指向滑动方向）。
* 判定：
  * 判定时刻（窗口同普通按键）鼠标横坐标落在 `[min(x_start,x_end), max(x_start,x_end)]`，
    且移动方向与谱面一致；
  * 游玩器记录判定时刻起 100 ms 内**最准确的一刻**：到达时立即 EXACT，否则保留最好等级，
    过线 100 ms 收尾；没有位移记 Break。
  * 滑动长度任意（编辑器允许把滑键画得很短，甚至短到只剩箭头的最小显示长度）。
* 合法性：滑键所在时刻如果存在空域，滑键横向范围必须与空域**相交或紧贴**。

### 4.6 鼠标点击按键（`type: "click"`）

* 语义：判定时刻，鼠标**点击**在这个按键的横向范围内（**左键 / 右键均可**）。
* 显示：**左右两条红色竖线**标出范围 + **中间一条红色横线**把它们连起来
  （粗细都与 6K 按键的中心实线相同）+ 中央一个**固定大小**的**红色实心菱形**
  （菱形大小不可编辑，也不是谱面字段）。
  两条竖线的间距 = `2 × radius`（按判定时刻的像素比例换算），高度与 6K 单键相同；
  **中间横线与菱形都以判定时刻为垂直中点**（时间网格线穿过它们）。
  它是**最上层**物件：与滑键 / 空域重叠时也压在最上面。
* 判定：判定时刻（窗口同普通按键）鼠标横坐标落在 `[center − radius, center + radius]`。
  按下即命中，不需要拖动，也不检查按下的位置在竖直方向（鼠标平面只有横向坐标）。
* 合法性：
  * 与滑键相同 —— 该时刻要么没有空域，要么与空域相交 / 紧贴；
  * **同一时刻不能出现两个鼠标点击按键**（即使横向不重叠）。

## 5. 坐标系与“出界”

* 鼠标平面的横向位置**不裁剪**：谱面里允许出现 `center = −0.2` 或 `1.3` 的物件，
  游玩器照常显示与判定（超出屏幕就贴在边缘显示）。
* 编辑器在**启用横向辅助网格**时才会吸附并把新物件夹进 `0..1`；
  未启用时按鼠标真实位置落点。也就是说：格子只是编辑辅助，**不是**谱面限制。

## 6. 图层顺序（可读性优先）

即使作者写出非法重叠，渲染与命中也要按下面的顺序，保证画面可读、点击不误选：

```
自下而上：多轨长按 → 单轨长按 → 多轨单键 → 单轨单键 → 空域 → 左右滑键 → 鼠标点击按键
```

* 多轨物件按**跨越轨道数降序**绘制（跨得越多越在下层）。
* 鼠标平面物件整体压在 6K 物件之上（半透明，交叠处依然看得见下面的按键）。
* 命中优先级与绘制顺序完全一致（后画的先被点到）。

## 7. 复用的基础模块

| 需求 | 复用点 |
| --- | --- |
| 谱面读写 | `io/chart_io.py`（普通 JSON，扩展名 `.json`）、`model/chart.py` |
| 拍 ↔ 秒 / 歌曲位置 | `model/timing.py` |
| 流速积分 / 位置反推 | `model/speed.py` 的 `SpeedGroup.distance()` / `judging_distance()` |
| 空域边界曲线与缓动 | `model/notes.py` 的 `BoundaryCurve` / `MouseRegion.left_at()/right_at()` |
| 物件几何（含命中框） | `ui/geometry.py`（`HitCache`、`note_geometry()`） |
| 合法性检查 | `model/validate.py`（`validate_chart()` / `format_report()`） |
| 变速播放（慢放降调，重采样实现） | `audio.py`（`set_rate()`，0.01 ~ 1.0x） |
| 延迟校准 | 全局设置 `audio_latency_ms` + `AudioPlayer.heard_position_ms()` |
| 游玩器世界几何 | `game/frame.py`（软件渲染与 Panda3D 渲染共用） |

## 8. 非法谱面的处理策略

编辑器**允许**写出非法谱面（这是刻意保留的创作自由）。游玩器不拒绝加载，按下面的策略降级：

1. 同一轨道重叠的按键：全部保留、全部参与判定（各自独立命中）；
2. 长按被其它按键覆盖：长按照常判定，覆盖它的按键也照常判定；
3. 两个点击按键同一时刻：都保留，命中任意一个即算命中，另一个记为 Break；
4. 滑键 / 点击按键与空域不相交：该时刻按“空域内点击”处理失败，其余物件照常；
5. 速度组流速为 `0` 或负数时，物件可能长时间停在判定线上或反向飞离：
   判定只认**判定时刻**，不用“屏幕上是否还在下落”来判断漏接。

## 9. 实现对应

1. **判定核心**：`game/judge.py` —— 判定窗口、长按 / 空域区间、滑键吸附、准度与分数。
2. **输入与状态机**：`game/app.py` 把键盘 / 鼠标事件映射到轨道与横向坐标。
3. **位置系统**：`model/speed.py` 的 `SpeedGroup.distance()`（不用线性时间插值）。
4. **计分 / 连击 / 准确度 / 结算**：`game/judge.py` 统计，`game/app.py` 绘制。
5. **渲染**：软件与 Panda3D 两条路径共用 `game/frame.py` 的世界几何，
   图层顺序由 `model/notes.py::layer_rank()` 统一给出。
